# Glossar

| Begriff / Abkürzung                   | Bereich              | Verwendet wenn                                                                                           | Primär genutzt von        | Vorkommen         |
| ------------------------------------- | -------------------- | -------------------------------------------------------------------------------------------------------- | ------------------------- | ----------------- |
| `add-focuslist-action`                | Skill                | eine neue FocusList-Aktion konsistent zur bestehenden Struktur ergänzt wird                              | Teilnehmer:innen          | Modul 5           |
| Agentisches Spektrum                  | Konzept              | eingeordnet wird, wie autonom eine AI-Interaktion abläuft                                                | Teilnehmer:innen, Trainer | Modul 1           |
| `applyTo`-Pattern                     | Copilot/Instructions | eine `*.instructions.md`-Datei auf bestimmte Dateipfade begrenzt wird                                    | Teilnehmer:innen          | Modul 4           |
| Blockierender Hook                    | Automatisierung      | ein Hook den Commit bei Fehlschlag verhindert statt nur zu warnen                                        | Teilnehmer:innen          | Modul 8           |
| Changelog-Eintrag                     | Doku                 | eine versionierte Notiz zu einer konkreten Änderung erzeugt wird                                         | Teilnehmer:innen          | Modul 6           |
| Chat-Modus                            | Copilot              | offener Dialog mit vollem Werkzeugzugriff ohne feste Rolle genutzt wird                                  | Teilnehmer:innen          | Modul 7           |
| `copilot-instructions.md`             | Copilot              | repoweite Leitplanken implizit in jeden Kontext eingemischt werden sollen                                | Teilnehmer:innen          | Modul 4           |
| Custom Agent (`*.agent.md`)           | Copilot              | ein eigener Systemprompt mit eingeschränkten Tools für eine feste Rolle gebraucht wird                   | Teilnehmer:innen          | Modul 7           |
| Doku-Prompt                           | Copilot/Prompts      | README/Changelog/Docstrings aus dem aktuellen Codestand abgeleitet werden                                | Teilnehmer:innen          | Modul 6           |
| Explizite Regel                       | Instructions         | eine Konvention konkret genug formuliert werden muss, um in einem Diff überprüfbar zu sein               | Teilnehmer:innen          | Modul 4           |
| Falsche Annahme                       | Qualität/Review      | eine unbegründete fachliche Entscheidung des Modells erkannt wird                                        | Teilnehmer:innen          | Modul 3           |
| `#file`                               | Copilot Chat         | der Inhalt einer bestimmten Datei explizit referenziert wird                                             | Teilnehmer:innen          | Modul 2           |
| Ghost Text (Inline-Vervollständigung) | Copilot              | ein grau angezeigter Vorschlag direkt im Editor erscheint                                                | Teilnehmer:innen          | Modul 2           |
| Halluzination                         | LLM/Qualität         | ein plausibel aussehender, aber faktisch falscher Vorschlag entsteht                                     | Teilnehmer:innen, Trainer | Modul 1, Modul 3  |
| Hook                                  | Automatisierung      | ein Skript automatisch bei einem Git-Ereignis ausgeführt wird                                            | Teilnehmer:innen          | Modul 8           |
| Kontext                               | LLM                  | alles für die Anfrage sichtbare (offene Editoren, Selektion, referenzierte Dateien) gemeint ist          | Teilnehmer:innen, Trainer | Modul 1, Modul 2  |
| Kontextfenster / Context Window       | LLM                  | die begrenzte Textmenge gemeint ist, die ein Modell gleichzeitig berücksichtigen kann                    | Teilnehmer:innen          | Modul 1, Modul 10 |
| LLM (Large Language Model)            | Grundlagen           | ein Modell, das Text inkl. Code tokenweise vorhersagt, erklärt wird                                      | Teilnehmer:innen          | Modul 1           |
| MCP-Client                            | Automatisierung      | die Anwendung gemeint ist, die sich mit einem MCP-Server verbindet                                       | Teilnehmer:innen          | Modul 8           |
| MCP-Konfiguration                     | Automatisierung      | einem Client mitgeteilt wird, wie ein MCP-Server gestartet/erreicht wird                                 | Teilnehmer:innen          | Modul 8           |
| MCP-Server (Model Context Protocol)   | Automatisierung      | ein Prozess Tools/Ressourcen über das Protokoll bereitstellt                                             | Teilnehmer:innen          | Modul 8           |
| OpenSpec                              | Spec-Driven Dev      | Specs in `openspec/changes/`, `openspec/in-progress/`, `openspec/archive/` verwaltet werden              | Teilnehmer:innen          | Modul 9           |
| Ownership                             | Verantwortung        | die Verantwortung für Korrektheit, Wartbarkeit, Sicherheit eines Codebestandteils gemeint ist            | Teilnehmer:innen, Trainer | Modul 1           |
| Problem Matcher                       | VS Code              | Task-Ausgabe automatisch Fehlern/Warnungen im Editor zugeordnet wird                                     | Teilnehmer:innen          | Modul 8           |
| Prompt-Bibliothek                     | Copilot/Prompts      | mehrere klar abgegrenzte `*.prompt.md`-Dateien gesammelt werden                                          | Teilnehmer:innen          | Modul 6           |
| `*.prompt.md`                         | Copilot              | eine gespeicherte, wiederverwendbare Prompt-Vorlage mit Frontmatter genutzt wird                         | Teilnehmer:innen          | Modul 6           |
| Review-Prompt                         | Copilot/Prompts      | bestehender Code gegen definierte Konventionen geprüft wird, ohne ihn zu ändern                          | Teilnehmer:innen          | Modul 6           |
| Risikoarten                           | Qualität             | funktionale Fehler, veraltete/unsichere Muster, Lizenzfragen, übersehene Edge Cases unterschieden werden | Teilnehmer:innen          | Modul 1           |
| `#selection`                          | Copilot Chat         | nur der aktuell markierte Codeabschnitt referenziert wird                                                | Teilnehmer:innen          | Modul 2           |
| `SKILL.md`                            | Copilot              | ein wiederverwendbarer, mehrstufiger Ablauf für eine wiederkehrende Aufgabenart definiert wird           | Teilnehmer:innen          | Modul 5           |
| Spec-Driven Development               | Methodik             | eine Spezifikation vor der Implementierung geschrieben und geprüft wird                                  | Teilnehmer:innen          | Modul 9           |
| Stilinkonsistenz                      | Qualität/Review      | unterschiedliche Schreibweisen/Strukturen für vergleichbare Fälle auftreten                              | Teilnehmer:innen          | Modul 3           |
| Strukturiertes Feedback               | Kursformat           | Rückmeldung sich auf konkrete Module/Übungen statt den Kurs pauschal bezieht                             | Teilnehmer:innen, Trainer | Modul 10          |
| Subagent                              | Copilot              | ein Agent von einem anderen Agenten/Prompt für eine Teilaufgabe aufgerufen wird                          | Teilnehmer:innen          | Modul 7           |
| Task                                  | VS Code              | eine in `.vscode/tasks.json` definierte, wiederverwendbare Befehlskette ausgeführt wird                  | Teilnehmer:innen          | Modul 8           |
| Token-Ökonomie                        | LLM                  | bewusst mit Kontextgröße umgegangen wird, um Präzision und Kosten auszubalancieren                       | Teilnehmer:innen          | Modul 10          |
| Ungeleitetes Prompting                | Methodik             | Anfragen an Copilot ohne Instructions/Skills, nur mit Konzeptdokument, gestellt werden                   | Teilnehmer:innen          | Modul 3           |
| Versionskette (v0-v7)                 | Projektstruktur      | der gesamte FocusList-Entwicklungsverlauf über alle Module referenziert wird                             | Teilnehmer:innen, Trainer | Modul 1, Modul 10 |
| `focuslist-test-agent`                | Custom Agent         | ein projektspezifischer Agent auf Test-Dateien in `tests/` eingeschränkt wird                            | Teilnehmer:innen          | Modul 7           |
